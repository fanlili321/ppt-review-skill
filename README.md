# ppt-review

银行螺丝钉直播/活动 PPT 成品复核 skill，供 Claude Code 使用。这是一个私有仓库，是 `ppt-review` skill 的**源代码托管地**——本地生效路径是 `~/.agents/skills/ppt-review/`（symlink 到 `~/.claude/skills/ppt-review/`）。

## 这个 skill 做什么

在成品 PPT 发给王磊（或任何正式审阅）之前，对**任意来源**的 PPT 成品（`.key` 或 PDF）做逐页检查——数据合理性、图表图例对应、颜色一致性、命名口径统一、图片清晰度、版式、提交流程。不限于哪个技能/团队做的，人工在 Keynote 里手工做的也适用。

只负责**复核已经做好的成品**，不生成、不编辑 PPT 内容本身：
- 生成/编辑 PPT 走 `live-ppt-builder`
- 飞书大纲的撰写/配图走 `outline-builder`

## 技术边界

实测过 Keynote 15.3 的 AppleScript 能力：
- ✅ 文字的字号、字体、颜色都能读到（脚本已封装）
- ❌ 形状/色块的填充颜色读不到具体色值
- ❌ 图片对象读不到源文件、也读不到原始像素分辨率

所以颜色一致性、图片清晰度这两项没法靠脚本自动判定，走"脚本导出结构化字号数据 + 导出每页 PNG 交给 AI/人目检"的混合方案。

## 复核维度（十大类）

数据核对 / 图表与图例 / 逻辑与结论 / 版式与可读性 / 特殊数据标注 / 文字与命名一致性 / 颜色一致性 / 图片清晰度 / 提交前流程 / 复核固定顺序。详见 `references/历史问题库.md`。

**已核实的口径（2026-08-28）**：资产分类命名（如"房产/股票/存款、债券、理财等"）是单份 PPT 专用口径，不是长期标准，不建立跨 PPT 的全局映射表；颜色一致性长期采用 deck 内自洽检查法，不建立全局色板。

## 文件结构

```
SKILL.md                     复核流程、技术边界、输出格式
references/
  历史问题库.md               复核检查项的完整知识来源（数据/图表/逻辑/版式/文字/流程十大类历史真实踩坑+速查表）
scripts/
  review_deck.py              只读复核工具：导出每页字号/字体/颜色结构化数据、导出每页PNG
```

## 使用前提

- 脚本执行前会自动检查 Keynote 是否已经打开着同名文件，检测到就报错中止——安全铁律，绝不碰用户打开着的文件。
- 复核只输出问题清单，不直接改 PPT；改完后建议再走一轮复核再发正式审阅。
