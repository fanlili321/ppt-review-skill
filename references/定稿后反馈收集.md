# 定稿后反馈收集（每期一次）

## 什么时候跑
- **每期定稿上传之后跑一次**，不在每轮修改后跑（每轮都跑会重复收集同一条、用户要确认多次）。
- 触发：用户说「定稿了」「已上传」「收集下这期反馈」；或 `live-ppt-builder`「定稿后」自动接上。
- 不是 `live-ppt-builder` 做的 PPT（汤爱学做的高净值、线下活动 PPT）也可以单独跑，来源换成对应的群和文档。

- 终点：现在。
- 先看文末「收集记录」，已收集过的时间段不再重复收集。

## 3. 每条反馈分类
| 类别 | 判断 | 去向 |
|---|---|---|
| A 成品可查的通用规则 | 下期别的主题也会遇到，且从成品本身能查出来 | `references/历史问题库.md` 对应章节 |
| B 制作做法 | 从成品看不出来，属于怎么做、怎么取数、怎么沟通 | `live-ppt-builder/rules/老板反馈规则.md` 第二节 |
| C 本期一次性内容意见 | 只针对本期主题的观点、措辞、选材（如「这页换成 300 价值/成长」） | 不写入，只在汇总里列出 |
| D 已有规则 | 问题库或老板反馈规则里已经有 | 不新增条文；有好案例的，在原条目后补一句「（NNN 期再次出现：…）」 |

判断 A/D 前先 grep 问题库和老板反馈规则的关键词（例如「两位小数」「数据来源」「彭博」「口径」），避免重复。

## 4. 列给用户确认（在聊天里，不直接写文件）
按下面格式列出，A、B 类逐条给拟写条文，C、D 类一句话带过：

| # | 日期/来源/谁说的 | 反馈原文（摘要） | 类别 | 拟写入位置 | 拟写条文 |
|---|---|---|---|---|---|

最后一句汇总：「本期共收集 X 条反馈：新增规则 A 类 a 条、B 类 b 条；已有规则 d 条；本期一次性 c 条。」

## 5. 用户确认后写入
- A 类：加到 `历史问题库.md` 对应章节末尾（按内容归类，不按期数新开章节），带日期和期数；文件开头的整理说明列表追加一条（编号顺延）；有新编号的同步加进文末速查表。
- B 类：加到 `live-ppt-builder/rules/老板反馈规则.md` 第二节末尾，编号顺延；属于交付流程某个环节的做法，写进 `live-ppt-builder/rules/复核记录与交付.md` 对应环节或「通用」小节，不按期数往文末追加。
- 如果某条规则重要到每次复核都必须看（类似「星级来源」），同时在 `SKILL.md` 对应步骤里加一句指引。
- 写完在下方「收集记录」追加一行。
- skill 源码另有 GitHub 仓库（`~/github/ppt-review-skill`、`~/github/live-ppt-builder`），同步和提交走分支 + PR，用户同意后再做。
